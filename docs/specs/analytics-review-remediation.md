## Behavior and contracts

- `excludeActiveDeletionMarkers` and its direct caller `OperationalEventTransforms.silver` return `Either[AnalyticsError, DataFrame]`; schema validation covers event `subjectToken`, event `subjectTokens`, and marker `subjectToken`. Every direct caller lifts `Left` into IO: ingestion in `AnalyticsBatchIngestionStage`, the `safeValid` flow in `AnalyticsBatchSilverStage`, and `OperationalEventTransforms.silver` at its stage call site. `withSubjectToken` remains `DataFrame` because it has no current explicit expected-error branch.
- Mongo lock owner UUID and deadline are already computed inside an `IO.flatMap` callback and therefore are deferred; preserve this and add a construction-vs-run check. `MongoPublisherStream.transaction` currently reads its retry deadline eagerly. Move deadline creation and checks to an injectable monotonic `Clock[IO]`, preserving one deadline through all retry paths.
- Report reservation uses one shared CAS-increment/refetch helper returning refreshed generation and revision, while preserving existing-run, new-run, conflict, and retry behavior. Verify idempotent same-range reservation, changed-range conflict, and no leaked revision increments after conflict/failure.
- Offset JSON correctly escapes topic strings, including quotes, backslashes, and control characters; ordering and numeric values stay unchanged.
- Gold schema failure is lifted through `lakehouseEither`. The eager Gold transform is named `timeToHireAction`. SHA-256 hex output remains byte-for-byte identical through `AnalyticsDigest.sha256Hex(bytes)`. The erasure poll loop uses `foreverM` and remains cancellable.
- Package target and ownership: `domain` contains `AnalyticsContracts` (including pure `PartitionOffsetRange`), pure report values and retention/status policies, `SubjectPseudonymizer`, and `AnalyticsDigest`; no separate `AnalyticsRanges` file is needed. `AnalyticsOffsetRanges` is Spark-backed and lives in `adapter.spark`. `errors` contains shared SDK-independent `AnalyticsError`. `service.batch` owns `AnalyticsLakehouseLock` and publisher ports; `service.erasure` owns claim/state/failure policy and persistence port; `service.keyretirement` owns pure authorization values, validation, and store port. `config` owns runtime config. `adapter.spark` owns Spark transforms, Spark-coupled batch/erasure workflows, and lakehouse operations; `adapter.kafka` owns Kafka retention/fencing; `adapter.mongo` owns Mongo repositories, session/publisher bridges, and key-retirement preparation persistence; `adapter.local` owns filesystem/Docker inspection and local writer exclusion; `cli` owns the six public runnable entrypoints. Split `AnalyticsSubjectPrivacy.scala` into pure pseudonymizer and Spark privacy adapter; split `HmacKeyRetirementAuthorization.scala` into pure authorization types/validation and Mongo persistence; keep the Mongo marker adapter's Spark DataFrame construction as an explicit adapter-to-adapter composition because it implements the batch marker-source contract. Put the pure report output model in `domain`. Place `AnalyticsKeyRetirement` and `HmacKeyRetirementCoordinator` with Spark-facing orchestration in `adapter.spark`. Narrow package visibility where package moves permit it. Within one SBT project public imports still permit cross-layer dependencies, so this is a visible namespace boundary rather than a complete compiler-enforced DAG. Update `docs/big-data-architecture.md`, both Dockerfiles, `scripts/run-hmac-key-rotation-proof.sh`, `docs/specs/hiring-analytics-lakehouse.md`, and tests for all six entrypoints: `HiringAnalyticsBatchMain`, `AnalyticsErasureWorkerMain`, `AnalyticsErasureRepairMain`, `AnalyticsKeyRetirementAuditMain`, `HmacKeyRetirementAuthorizationMain`, and `HmacKeyRetirementFixtureMain`. ## Review points 5–11 amendment

- Source facts: `HiringAnalyticsBatch` has optional publisher/manifest writer and a process-local lock default; `AnalyticsBatchStageRuntime` exposes twelve capabilities to every stage. All analytics use cases and adapters currently use `IO`, including worker polling and lease renewal. `AnalyticsErasureStore` has a single 20-method port and boolean matched-update results. `PartitionOffsetRange` and runtime config repeat raw range checks; paths expose a public case-class constructor; Kafka JSON and JAAS values are concatenated. The analytics build does not declare Circe.
- Decisions: genericize every production analytics port, use-case/workflow, and Spark/Mongo/Kafka/local adapter in `F[_]`; only CLI `IOApp` composition chooses `IO`. Use `Async[F]` for blocking effect boundaries, `Temporal[F]` for time/sleep, Cats Effect `Clock[F]` for wall/monotonic time, and injected `Logger[F]`. Use required explicit collaborators and stage-specific ports. Ingestion gets `ManifestStore[F]`, `DeltaWriter[F]`, `Clock[F]`, and Spark execution; Silver gets `DeltaReader[F]`, `DeltaWriter[F]`, quarantine ID generation, and Spark execution; KeyContinuity gets authorization lookup, clock, Spark execution, and Delta access; Erasure gets the Delta access/privacy configuration and evidence-file bound. Split erasure persistence into queue, progress, and barrier capabilities. Map only lease-guarded matched-update Booleans (`persistBarrier`, Delta progress writes, release/failure/defer, renew, and advance) to `ErasureUpdate.Applied | LeaseLost`; retain Booleans for actual predicates such as publisher drain/readiness. Use `RunId` and a new opaque `RangeFingerprint` at reservation boundaries. Construct validated ranges/paths only through accumulating smart constructors; preserve null guards at Java/Spark interop only. Add Circe for connector JSON and use Typesafe Config's concise quoted-value renderer, validated by Kafka `JaasConfig`, for JAAS option values.
- Compatibility: retain Kafka JSON member ordering and values, JAAS credentials semantics, erasure lease/CAS predicates, report publication ordering, retry/cancellation behavior, persisted data shape, and all external wire contracts.
