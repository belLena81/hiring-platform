## Behavior and contracts

- `excludeActiveDeletionMarkers` and its direct caller `OperationalEventTransforms.silver` return `Either[AnalyticsError, DataFrame]`; schema validation covers event `subjectToken`, event `subjectTokens`, and marker `subjectToken`. Every direct caller lifts `Left` into IO: ingestion in `AnalyticsBatchIngestionStage`, the `safeValid` flow in `AnalyticsBatchSilverStage`, and `OperationalEventTransforms.silver` at its stage call site. `withSubjectToken` remains `DataFrame` because it has no current explicit expected-error branch.
- Mongo lock owner UUID and deadline are already computed inside an `IO.flatMap` callback and therefore are deferred; preserve this and add a construction-vs-run check. `MongoPublisherStream.transaction` currently reads its retry deadline eagerly. Move deadline creation and checks to an injectable monotonic `Clock[IO]`, preserving one deadline through all retry paths.
- Report reservation uses one shared CAS-increment/refetch helper returning refreshed generation and revision, while preserving existing-run, new-run, conflict, and retry behavior. Verify idempotent same-range reservation, changed-range conflict, and no leaked revision increments after conflict/failure.
- Offset JSON correctly escapes topic strings, including quotes, backslashes, and control characters; ordering and numeric values stay unchanged.
- Gold schema failure is lifted through `lakehouseEither`. The eager Gold transform is named `timeToHireAction`. SHA-256 hex output remains byte-for-byte identical through `AnalyticsDigest.sha256Hex(bytes)`. The erasure poll loop uses `foreverM` and remains cancellable.
- Package target and ownership: `domain` contains `AnalyticsContracts` (including pure `PartitionOffsetRange`), pure report values and retention/status policies, `SubjectPseudonymizer`, and `AnalyticsDigest`; no separate `AnalyticsRanges` file is needed. `AnalyticsOffsetRanges` is Spark-backed and lives in `adapter.spark`. `errors` contains shared SDK-independent `AnalyticsError`. `service.batch` owns `AnalyticsLakehouseLock` and publisher ports; `service.erasure` owns claim/state/failure policy and persistence port; `service.keyretirement` owns pure authorization values, validation, and store port. `config` owns runtime config. `adapter.spark` owns Spark transforms, Spark-coupled batch/erasure workflows, and lakehouse operations; `adapter.kafka` owns Kafka retention/fencing; `adapter.mongo` owns Mongo repositories, session/publisher bridges, and key-retirement preparation persistence; `adapter.local` owns filesystem/Docker inspection and local writer exclusion; `cli` owns the six public runnable entrypoints. Split `AnalyticsSubjectPrivacy.scala` into pure pseudonymizer and Spark privacy adapter; split `HmacKeyRetirementAuthorization.scala` into pure authorization types/validation and Mongo persistence; keep the Mongo marker adapter's Spark DataFrame construction as an explicit adapter-to-adapter composition because it implements the batch marker-source contract. Put the pure report output model in `domain`. Place `AnalyticsKeyRetirement` and `HmacKeyRetirementCoordinator` with Spark-facing orchestration in `adapter.spark`. Narrow package visibility where package moves permit it. Within one SBT project public imports still permit cross-layer dependencies, so this is a visible namespace boundary rather than a complete compiler-enforced DAG. Update `docs/big-data-architecture.md`, both Dockerfiles, `scripts/run-hmac-key-rotation-proof.sh`, `docs/specs/hiring-analytics-lakehouse.md`, and tests for all six entrypoints: `HiringAnalyticsBatchMain`, `AnalyticsErasureWorkerMain`, `AnalyticsErasureRepairMain`, `AnalyticsKeyRetirementAuditMain`, `HmacKeyRetirementAuthorizationMain`, and `HmacKeyRetirementFixtureMain`. Package rollback is code-only: restore previous paths/FQCNs and references atomically if compile or entrypoint checks fail; no persisted state changes.
