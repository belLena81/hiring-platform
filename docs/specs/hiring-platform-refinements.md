# Hiring platform refinements

## Identity and scope

- Task: one specification for every refactoring item that is still open after the completed consolidation and remediation specifications were removed on 2026-10-30. Cross-cutting; no roadmap phase. The removed files and their evidence stay in git history (see [Completed work recorded from removed specifications](#completed-work-recorded-from-removed-specifications)).
- Status: in progress. Each item below carries its own status; nothing here is newly authorized. An item that its source specification had already authorized says so; every other item needs its own task request before implementation.
- Coordinator: Product Manager. Owners per item.
- User outcome: a session can resume the refactoring from one list, with the original acceptance IDs, the gate each item still owes, and its relation to the MVP (local) claim in [development milestones](../development-milestones.md#mvp-local-conditions-and-status).
- Specifications that stay in place and are not repeated here:
  - [Analytics data model refactoring](analytics-data-model-refactoring.md): the active slice spec (MVP condition 1). Its remainder is listed in section A for sequencing only.
  - [Hiring MongoDB schema consolidation](hiring-mongo-schema-consolidation.md): locally complete; the Atlas Local gates are user-run (section D).
  - [Distributed data reliability improvements](distributed-data-reliability-improvements.md): a proposed plan, not started; the owner decides which items precede MVP.
  - [Effect-polymorphic services](effect-polymorphic-services.md), [hiring saga orchestration](hiring-saga-orchestration.md) and [dependency circuit breakers](dependency-circuit-breakers.md): done locally and kept as the design records that `ARCHITECTURE.md`, `docs/api.md` and the glossary cite. Their remaining verification gates are in section H.
- Non-goals (carried over from the sources): GraphQL federation or stitching, batch mutations over several applications, frontend assets or a Node toolchain, a role-model or status-transition change, real providers or paid infrastructure, Atlas cloud (`.C`) gates, binary UUID `_id`s, a per-document `schemaVersion`, splitting the polymorphic interview collections, renaming lease fields, TTL on Failed outbox or embedding-work rows, partitioning or liquid clustering in analytics.
- Dependencies: the pre-MVP contract policy in [schema evolution](../schema-evolution.md) applies until the owner explicitly asks to start versioning (including API versioning) and migration scripts for schema changes (database, Kafka and so on) (owner decision 2026-11-08; the owner calls that point the first cloud release). Under it, API and analytics shape changes in this list are implemented directly, with no migration, backfill or legacy-compatibility code. Operational MongoDB changes in this list use the versioned migration ledger.
