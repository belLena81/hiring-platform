## Decision record

- Status: accepted by the user, 2026-10-14.
- Context: ports and services are fixed to `IO`. Time and ID effects are already injected (`Clock[IO]`, `UUIDGen[IO]`), but sleeping, racing and fiber code is only testable in real time or by hand-rolled seams. Analytics already uses `F[_]`; the two builds follow different styles.
- Options considered:
  1. Keep concrete `IO` (the documented default). Lowest cost; no benefit for time-driven worker tests.
  2. Full migration to tagless final `F[_]` (chosen). Gives `TestControl` tests for sleep/race workers, consistent style with analytics, and a shared base for the Saga engine and circuit breaker.
  3. Migrate only workers. Smaller, but leaves the port aliases fixed to `IO` and the two styles mixed inside one build.
- Tradeoffs accepted: roughly 28 ports and 19 services change; signatures gain a type parameter and context bounds; compile time may rise; `F[_]` constraint errors are harder to read than `IO` errors; temporary dual aliases exist during migration.
- Evidence required: compile-time before/after (EPS-07), unchanged test assertions (EPS-01), green race/fencing integrations (EPS-06).
- Revisit trigger: compile time grows by more than the EPS-07 limit, or a slice cannot keep test assertions unchanged.

## Target shape

```scala
type RepositoryF[F[_], A] = EitherT[F, RepositoryError, A]
type UseCaseF[F[_], A]    = EitherT[F, UseCaseError, A]
```

- `RepositoryF` and `UseCaseF` companions keep the current helper names (`ensure`, `found`, `repository`, `pure`, `raise`, `lift`, `fromEither`, `fromFEither`). Helpers require the least class: `Applicative[F]` for `pure`, `raise`, `fromEither`, `ensure`; `Monad[F]` where they flatten (`found`, `repository`); `Functor[F]` for `lift`.
- Ports become `trait JobRepository[F[_]]` and so on. Methods return `RepositoryF[F, A]`.
- Services take their ports and capabilities as constructor or `apply` parameters with bounds, not a blanket `Async`.
- Minimal constraint by kind:

| Kind | Constraint |
|---|---|
| CRUD and authorization services (Job, Application, Account, Idempotent, coverage, search session recording) | `Monad[F]` + `Clock[F]` + `UUIDGen[F]` (only those used) |
| Polling or retrying workers, handoffs, pipelines | `Temporal[F]` (`Concurrent[F]` where only `Queue`/`Deferred` is used) |
| `BackgroundWorker` and `Resource`-owned fibers | `Spawn[F]` (plus `Resource` via `MonadCancel`) |
| `InterviewPublication` heartbeat race | `Temporal[F]` |
| Adapters over Mongo, Kafka, HTTP, the password hasher | `Async[F]` |

- `IO` is fixed only in: `Main` (the `IOApp`), `runtime/` wiring (`MongoHiringRuntime` and its siblings), the Sangria adapter, and tests that choose `IO` as the runtime. The Mongo transaction runner's `IO` crossings listed at `docs/engineering-quality.md:15` stay `IO` or become `Async[F]` inside the adapter; they do not leak into ports.
- Pure `domain/` code is untouched.
- Temporary aliases: during slices 1-7, `UseCaseIO[A] = UseCaseF[IO, A]` and `RepositoryIO[A] = RepositoryF[IO, A]` keep unmigrated code compiling. Slice 8 deletes them.

## Rules

1. **No behaviour change.** No SDL, BSON, event envelope, error code, log field or configuration key changes. Persisted shapes and idempotency keys are untouched.
2. **Test assertions.** Existing test assertions are not edited. Test construction may change (type arguments, `IO` chosen at the call site). A needed assertion change is a stop signal and is recorded in the checkpoint with a reviewer.
3. **Least capability.** A type that needs only `Monad` and `Clock` must not require `Async`. Reviewers reject a blanket bound where a smaller one compiles.
4. **No leakage.** Ports never mention `IO`. Adapters may.
5. **No unsafe execution** in services or workers. Unsafe execution stays in the Sangria adapter.
6. **Cancellation and resources.** `Resource`, `guaranteeCase` and fiber supervision keep their current semantics. A detached fiber is not introduced; `Spawn` is used only through `Resource`/`background`.
7. **One slice, one buildable state.** Each slice compiles and passes `sbt test` on its own before the next starts.
8. **Time-driven tests.** Every worker with `sleep` or `race` gets a `TestControl` spec for its time behaviour (poll interval, restart delay, heartbeat versus publish). This needs `cats-effect-testkit` as a Test dependency of the root build; that is a build change in slice 1, same version as `catsEffectVersion`.
