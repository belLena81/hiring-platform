## Contracts

- Run an opt-in resource-managed streaming process with a configurable 10-second default trigger (interval must be positive and at most 10 seconds), Kafka `read_committed`, `failOnDataLoss=true`, default `maxOffsetsPerTrigger=1000` (bounded to 100,000), and explicit initial offsets for every Kafka partition. At checkpoint creation, compare the configured partition set with broker metadata and fail on missing or unexpected partitions. Never fall back to `latest`.
- Feed each `foreachBatch` frame into the shared ingestion and publication stages. Preserve coordinate/event-ID idempotency, quarantine, existing report formulas, K=10 suppression, generation/revision guards, and accepted Kafka offset gaps.
- Use stateless Spark topology and application-owned durable watermark/progress. Keep subject-attributed analytical facts under existing deletion/retention control. Native stateful Spark aggregation is out of scope.
- UTC daily windows close when `dayEnd <= previousWatermark`. Open days remain provisional. Advance only after successful guarded publication, monotonically to the greatest admitted, valid, unsuppressed event time minus 24 hours. Cap permitted near-future event times at the batch observation time. Quarantine events more than five minutes beyond observation. These intervals and the 30-day late-fact retention are fixed policy values. Empty, duplicate-only, suppressed-only, quality-blocked, erasure-pending, and idle periods do not advance progress.
- Recheck deletion markers on retries. Persist stable observation time and input identity before Delta writes; derive candidate watermark only from facts admitted after those refreshed checks. Delta progress, Mongo publication receipts and Spark checkpoint are separate durable boundaries and require explicit reconciliation.
- Keep late arrivals for closed days in a normalized 30-day late-fact dataset for explicit replay; store no raw envelope and disable Delta column statistics. Replay selects explicit coordinates, at most 1,000 records per run, preserves original expiry, and cannot advance watermark or bypass deletion/HMAC/generation guards.
- Bind checkpoints to stream/source/lakehouse/contract/settings identity. Missing or incompatible established checkpoints fail closed. Batch ingestion cannot bypass a lakehouse registered to streaming. Ownership is fail-closed, without expiry or automatic takeover.
- Isolate Spark callback execution through Cats Effect `Dispatcher`; query shutdown/cancellation must work while callbacks run, and waiting must not occupy the single Spark driver executor. Use `Resource` for all runtime ownership.
- Keep GraphQL shape and operational event envelope unchanged. Use HOCON/PureConfig and accumulated typed validation. No cloud provisioning, envelope versioning, legacy readers, automatic lakehouse reset, frontend, new report dimensions, dependency upgrades, or broad redesign.

### Implemented recovery and lifecycle decisions

- Permanent lineage and lakehouse registration distinguish initial bootstrap from established recovery. Checkpoint identity/query ID and retained Spark offset/commit evidence reconcile against Delta preparations/terminal outcomes and pinned Mongo receipts. An established checkpoint cannot be replaced automatically; actual process-loss/corruption evidence remains pending.
- `IngestionCommitted` is recoverable. A retry retains its admitted candidate only under the same immutable pinned decision and marker fingerprint; changed markers or superseded generation require a fresh bounded revision. Pre-existing duplicates cannot advance a recovered candidate. Publication and watermark commits remain guarded; real streaming recovery tests require rerun.
- Resolved in code: activation reads the explicitly selected grant ID; grant ID, `validFrom`, and `expiresAt` are covered by the evidence digest. Authorization requires `validFrom <= now < expiresAt`. Startup and callbacks recheck the grant, publication and acknowledgement have separate checks, and a resource-owned expiry timer terminates the query. Runtime cannot provision or renew grants; renewal requires restart. Mongo authorization enforcement and deployed role evidence remain an activation gate.
- Seven-day progress pruning retains unfinished inputs, required checkpoint batches, the watermark anchor and latest terminal state. Permanent sanitized lineage survives pruning. Receipt cleanup protects every retained stream lineage, active replay dependencies and current report/control receipts; compact completed replay details after 31 days while keeping digest bindings. Actual corrected journal/pruning fixtures pass 8/8; final combined runtime evidence remains pending.
- Accepted: target Bronze availability p95 under 30 seconds and Admin report freshness p95 at most 120 seconds. A 10-second trigger makes the Bronze target plausible but does not establish either SLO; measure healthy load, bursts/backlogs, lag, storage growth, and Spark resource use separately.
