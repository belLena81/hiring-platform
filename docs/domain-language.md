# Domain language and bounded contexts

The shared vocabulary for specs, tests, code, GraphQL names and agent handoffs. It names concepts and boundaries; field-level detail stays in the [domain wiki](wiki/domain-and-use-cases.md), [use cases](use-cases.md) and source. Behavior rules stay in [AGENTS.md](../AGENTS.md). When this page and source disagree, source describes implemented behavior: report the mismatch and fix the page.

Add a term here in the same change that introduces it, and only when it is new or ambiguous. Do not list every field. Use these words, not synonyms, in specs, acceptance criteria, test names and identifiers.

## Glossary

| Term | Meaning | Not to be confused with | Code / API name |
|---|---|---|---|
| Candidate | Role that searches visible open jobs, applies, and sees only their own applications | Admin/Recruiter accounts | `UserRole.Candidate` |
| Recruiter | Role that owns jobs and handles applications to those jobs | Any user who can see a job; only the owner (or Admin) may manage it | `UserRole.Recruiter` |
| Admin | Singleton operator provisioned only by explicit seed/config | A generic superuser role created at runtime | `UserRole.Admin` |
| MVP (local) | The local acceptance claim of 2026-11-07 (one scripted run holds all 13 use cases and the seven conditions in the development milestones were met). Condition 6 was reopened on 2026-11-10 and met again the same day at committed HEAD `d806d5c` (final independent QA PASS; code as of `ec66b09`). It was reopened on 2026-11-11 by the Phase 11 and Phase 11A commits and met again that day at committed HEAD `48f271a` (final independent QA PASS; owner check-local PASS 6 of 6 with the Atlas-gated and opt-in measurement tests skipped). It asserts no production rollout, no deployed result and no external-service certification | Production MVP, the demo deployment, or completion of any roadmap phase | documentation term (no code name) |
| full MVP | Older wording for MVP (local). It does not end or start the pre-MVP contract policy. [Schema evolution](schema-evolution.md) ends that policy when the owner explicitly asks to start versioning and do migration scripts on schema changes for db, kafka and so on, and API versioning (owner decision 2026-11-08; the owner calls that point the first cloud release). `AGENTS.md` and `CLAUDE.md` do not use the term. It does not mean a production or deployed MVP | Production MVP or deployed MVP | documentation alias (no code name) |
| First cloud release | The owner's name for the point at which the owner explicitly asks to start versioning and do migration scripts on schema changes for db, kafka and so on, and API versioning (owner decision 2026-11-08). That request ends the pre-MVP contract policy. Before it, new MongoDB indexes and validators are still ledger steps. It is not a date, a milestone or the MVP claim, and no such request or release is recorded | Local run, MVP (local) claim | documentation term (no code name) |
| Job | A posting owned by one Recruiter; Draft, Open or Closed | An Application | `Job`, `JobStatus` |
| Job state / Account state | The state of a Job (`Draft`, `Open`, `Closed(at)`) or of an account (`Active`, `Deleted(at)`) as one value, so a closed job always has its closing instant and a deleted account its deletion instant. The status enums (`JobStatus`, `AccountStatus`) are the labels clients filter by and stores compare | Two independent fields that could disagree | `JobState`, `AccountState` |
| Summary / Full job read | The two levels at which a list of jobs is read. `Summary` leaves out the posting text (description, requirements) and the embedding, and is chosen when the client's selection names neither; its jobs carry a blank description. `Full` reads everything a display read does | A job's lifecycle state | `JobProjection` |
| Publish / Close | Job lifecycle actions: Draft→Open, Draft/Open→Closed. `createJob` always creates a Draft, private to its owner and the Admin; publishing is when it becomes visible and `JOB_CREATED` is published. A closed job rejects new applications | Delete | `publishJob`, `closeJob` |
| Hidden is missing | A resource the caller may not see is answered exactly like one that does not exist (`NOT_FOUND`, same code and message), so existence is never revealed. `FORBIDDEN` is only for a role that lacks the right | Authorization failure for a visible resource | `NotFound(entity)` in services |
| Application | One Candidate's request for one Job; at most one per pair | A resume or profile | `Application` |
| Submit | Create an Application in `Created`, with initial history | Apply-then-accept in one step | `submitApplication` |
| Accept / Move to interview / Hire / Reject / Decline | Action-specific status transitions. Reject needs feedback; Decline needs a reason. All status actions require the owning Recruiter or the singleton Admin, except Decline, which the Application's own Candidate may also take (the candidate's withdrawal) | A generic status update (none exists) | `ApplicationLifecycle`, matching mutations |
| ApplicationStatus | Closed set: Created, Accepted, Declined, Interview, Hired, Rejected. Declined, Hired and Rejected are terminal | Job status | `ApplicationStatus` |
| ApplicationEvent | One append-only history record: previous/new status, actor, the role the actor acted in, UTC time, feedback/reason. Written atomically with the status | An operational event on Kafka | `ApplicationEvent` |
| Operational event | Fact published from the transactional outbox for consumers: at-least-once, idempotent consumers, one seven-field JSON envelope whose schema version (1) travels in a record header | ApplicationEvent history | outbox / Kafka publication |
| Publication wave | The up-to-four due outbox events one publisher poll claims (at most one per partition key) and sends in one Kafka transaction, every lease renewed before and during the send; on success each claim is marked Published independently, on failure the claims are released together (a claim whose lease was lost mid-send is left to expire instead); the release keeps the attempt charge only when the failure is the broker's unavailability or the wave held a single event, otherwise it is refunded and the events retry one per wave | A single outbox record's send; a Kafka producer batch | `OperationalEventKafkaRuntime.publishWave`, `releaseUncharged` |
| Schema version header | The `hiring-schema-version` record header naming the operational event contract version (1; absent means 1); a reader that does not know the version quarantines the record as `UnsupportedVersion` before reading the body | The body's `eventType`; a Mongo document version | `OperationalEventHeaders` |
| Producer worker identity | The configured per-instance worker id (`[a-z0-9][a-z0-9-]{0,63}`) that, with a role prefix, forms the stable Kafka transactional id of a publisher, so a restarted instance fences its predecessor; one id per running instance | A pod or host name; a consumer group member id | `ProducerWorkerId`, `KAFKA_WORKER_ID`, `INTERVIEW_WORKER_ID` |
| Producer generation | One initialized lifetime of a transactional producer, identified by a UUID drawn at initialization under a stable transactional id; registered per subject in `producer_registrations` and the unit that erasure fences and marks Fenced | Report generation, the analytics counter of a published report snapshot | `ProducerGenerationId`, `ProducerGeneration`, `InterviewPublisherGeneration` |
| Consumer receipt | Durable record that one consumer group handled one operational event: a unique insert keyed by consumer group and event id. A duplicate key means "already handled". Today the receipt is the whole consumer effect; its `expiresAt` is set from the receipt TTL at first consumption and raised, never lowered, by each duplicate delivery to that delivery's time plus the TTL | Mutation receipt (the stored outcome of an idempotent API request) or a provider idempotency record | `ConsumerReceiptRepository`, `consumer_receipts` |
| Deduplication window | The span a consumer receipt must cover: every message Kafka can still deliver, which is topic `retention.ms + segment.ms`, plus a 1-hour margin. The consumer refuses to start unless the receipt TTL is at least that span, re-reads the span every 5 minutes while running, and stops on a refusal | Kafka retention alone, which leaves out the active segment | `ConsumerReceiptWindow`, `ConsumerReceiptWindowRefused` |
| Provider idempotency contract | The adapter rule for an external effect. A call is applied at most once per idempotency key when the provider's own idempotency mechanism or a platform receipt answers repeats; a calendar adapter uses a durable send intent resolved by `lookup`, never a blind resend. A notification provider with none of these is at least once (SES email): an unknown outcome may be sent again, so a duplicate is possible and a silent loss is not. Proven by the shared provider contract suites (exactly-once and at-least-once variants) | The local ledger, which stores one receipt per key; a mutation's idempotency key | `InterviewNotificationProvider`, `InterviewCalendarProvider`, `Interview*ProviderContract`, `InterviewNotificationAtLeastOnceContract` |
| SES notification provider | The prepared Amazon SES email adapter behind `InterviewNotificationProvider`. Selected only by `kafka.interview.notifications.provider = ses` with `ses.enabled = true`; at least once; not activatable in this build because the SES client does not exist, and, with the interview runtime enabled, selecting it fails application startup | The ledger provider (the default, which sends nothing), or the calendar provider | `SesInterviewNotificationProvider`, `SesEmailClient`, `kafka.interview.notifications` |
| Interview workflow | Durable, conditional scheduling around Accepted→Interview; it adds no statuses | The status `Interview` | `domain/workflow` |
| Actor projection | The minimal user read used for authorization: id, role, account status and whether the Admin is the singleton. It never carries a profile, credential or embedding, and an authenticated request reads it once | The user profile or the whole user document | `ActorRecord`, `users.findActor` |
| Job ownership projection | The minimal job read used for authorization: id, owning Recruiter and status | The job for display, which carries the description | `JobOwner`, `jobs.findOwner` |
| Status write | The one session-scoped write that moves an Application to its next status: `$set status, updatedAt` guarded by the previous status and the stored owner facts, then the ApplicationEvent, then the outbox rows, in one transaction. The API status actions, the interview hiring commit and the interview cancellation all use it. Invariant: the stored status is the `newStatus` of the latest ApplicationEvent | Replacing the application document; a generic status update | `ApplicationStatusWrite`, `ApplicationStatusInvariant` (tests) |
| Embedding | Derived search data on a Job or Candidate; never operational truth | A user-visible field | embedding work |
| Embedding freshness | Whether the stored embedding of one Job or Candidate matches the entity now: `Current` (content hash matches, and the model matches when an expected model is given), `ContentChanged` (hash differs from the current searchable text), `ModelMismatch` (hash matches, model differs from the expected model; produced only with an expected model) or `NotEmbedded` (no embedding metadata). Independent of repair state | Embedding repair state (whether work is queued); the vector itself | `EmbeddingFreshness`, report `freshness`, [embedding coverage report](specs/embedding-coverage-report.md) |
| Embedding repair state | Whether a repair is scheduled for one Job or Candidate, from its `embedding_work` row: `NoQueuedWork` (no row), `Waiting` (Ready), `Retrying` (Retry), `InProgress` (Processing with `leaseUntil > now`), `LeaseExpired` (Processing with `leaseUntil <= now`, claimable again) or `Failed` (Failed row, with a separate failure reason). Independent of embedding freshness: a value from one dimension never describes the other | Embedding freshness (whether the embedding matches the entity); the Saga status `Repair` | `EmbeddingRepairState`, report `repairState`, [embedding coverage report](specs/embedding-coverage-report.md) |
| Orphaned gap | A searchable Job or Candidate whose freshness is not `Current` and whose repair state is `NoQueuedWork`, so nothing will ever repair it. The `NO_ORPHANED_GAP` check fails on one | Stuck work (queued but late), or a non-current entity that still has a repair queued, which is expected while repair runs | `NoOrphanedGap`, [embedding coverage report](specs/embedding-coverage-report.md) |
| Stuck work | Queued repair work (`Waiting`, `Retrying`, `InProgress` or `LeaseExpired`) that has waited longer than three durable retry caps (`3 x durableRetryCapMillis`) past its `availableAt`. A live claim whose `availableAt` is that old counts too. The `NO_STUCK_WORK` check fails on one | Orphaned gap (no work exists at all); an expired lease alone, which only makes work claimable again | `NoStuckWork`, [embedding coverage report](specs/embedding-coverage-report.md) |
| Consent | Candidate's recruiter-search opt-in; governs candidate matching visibility | Authentication | `CandidateProfile` |
| Late fact | Analytics event that arrives after its UTC day is closed; retained with an expiry and excluded from published reports until replayed | A quarantined (invalid or conflicting) event | `AnalyticsLateFactStage` |
| Candidate watermark | Event-time bound a streaming batch proposes; becomes the report watermark only after the batch's terminal commit | Kafka offset or Spark checkpoint position | `candidateWatermark` |
| Erasure marker | Durable record that a deleted account's subject must be excluded from every analytics write; a `Pending` or `Processing` request's marker also hides the report, while a `Complete` marker only excludes replayed events (`ActiveDeletionMarkers.erasureInProgress`) | The account tombstone in operational MongoDB | active deletion marker |
| Erasure completion budget | Configured upper bound on the time from Delta purge to verified physical erasure, derived from the retention horizons (worst case = the largest of Kafka retention plus segment roll, one UTC day plus Delta log retention, and vacuum safety). Startup refuses a configuration whose worst case exceeds it; default 21 days against a 15-day worst case | The retention horizons it is derived from, which set the physical timings; the Kafka barrier is still checked against real broker offsets | `AnalyticsRetentionSettings.erasureCompletionBudget`, `ErasureCompletionRule` |
| Durable boundary | One of seven persisted points in a streaming batch (Prepared … TerminalCommitted) from which recovery resumes | A Spark micro-batch commit | `StreamingDurableBoundary` |
| Stream owner | Exclusive Mongo-held ownership of one lakehouse by one running stream | The per-callback lakehouse mutex | `MongoAnalyticsStreamingRegistry` |
| Activation grant | Immutable, expiring authorization that permits a streaming process to start | A user role or JWT | `StreamingActivationGate` |
| Lexical-query facet | Bucket counts (skills, countries, cities, remote) for a job text query, computed from the authoritative jobs collection restricted to a bounded set of lexically matched IDs (cap 1000). Payload field `coverageLimit`: null (counts cover every matching Open job) or the cap (more than the cap matched; counts cover only the top-N by lexical score, never a total). Search failure is a typed sanitized `FACETS_UNAVAILABLE` (`SEARCH_UNAVAILABLE`). Never read from the search index | Structured facet (no text query); search-index facet collector | `jobDiscoveryFacets(query:)`, `HDQ-12` |
| Human label gate | Pending sign-off by a human domain reviewer of fabricated relevance judgments against an exact corpus digest. Criterion suffix `.H`; blocks ranking adoption whatever the `.L`/`.C` outcomes | Automated or agent rubric verification | `SEB-02.H` |
| Atlas-compatible local gate | Search acceptance evidence from the $0 Atlas Local container (`compose.atlas-local.yaml`, mongot, loopback). Criterion suffix `.L`. Proves branch behavior and runs a rehearsal; never Atlas acceptance; never adopts an index, query or vector tuning change. Application-side ranking is the one exception: a `.L` run with real provider embeddings may serve as SEB-08 evidence for it (owner decision 2026-11-10), and adoption still needs SEB-02.H and the other gates | Atlas cloud gate | `MVR-xx.L`, `DisposableAtlas.deployment = local-container` |
| Atlas cloud gate | Search acceptance evidence from an authorized disposable cloud Atlas deployment: native `$rerank`, cloud-scale recall/latency, index memory/storage, telemetry. Criterion suffix `.C`; the only gate that can adopt a vector tuning change | Atlas-compatible local gate | `MVR-xx.C` |
| Circuit breaker | Dependency guard around one outbound adapter (closed, open, half-open). While open it rejects calls without touching the dependency; it counts only dependency-unavailability failures, never business outcomes. Process-local; applied to Voyage, Atlas discovery, the Kafka publisher and Mongo writes only. Only the Mongo-writes breaker affects readiness. See [dependency circuit breakers](specs/dependency-circuit-breakers.md) | Retry or timeout; readiness probe | `CircuitBreaker` |
| Saga | Durable, revisioned multi-step workflow across a boundary transaction cannot cover (calendar, notification, retention). Advances only through a pure decision plus an atomic store write. Implemented for interview scheduling only; cancel/reschedule, subject cleanup and account erasure are not Saga definitions. See [hiring saga orchestration](specs/hiring-saga-orchestration.md) | A single-transaction status change; an outbox publication | `SagaDefinition`, `SagaEngine` (scheduling definition: `InterviewSchedulingSaga`) |
| Saga step | One named unit of a Saga with an idempotency key, a retry budget and a declared undo (Compensation or Irreversible) | An application status | `SagaStep` |
| Compensation | A semantic undo of a completed Saga step (for example releasing a calendar reservation). Idempotent, bounded retry; failure leads to Repair | Database rollback | `StepUndo.Compensate` |
| Irreversible step | A Saga step that cannot be undone (for example a delivered notification in the scheduling definition); recovery is forward-only and its reason is declared. Account tombstone and elapsed retention are not Saga steps; they keep their existing forward-only policies | A step without compensation by omission | `StepUndo.Irreversible` |
| Repair | Saga status `RepairRequired`: automatic progress stopped and an Admin action resumes by lookup, never by repeating an effect with a new key | Retry | `SagaStatus.RepairRequired` |
| Content revision | `version` on a user or job document: advances only when the content changes, and optimistic edits and embedding writes compare against it. Derived data (embeddings) and conflict fences never advance it | Admission fence; schema version | `MongoJobContentUpdate`, [MSC-01](specs/hiring-mongo-schema-consolidation.md) |
| Admission fence | `jobs.admissionFence`: optional Int64 counter (absent = 0, internal, not in the domain model or GraphQL) that `$inc` by application submission and interview scheduling so those writes conflict with a concurrent closure of the same job without changing `version` or `updatedAt` | Content revision; subject fence | `MongoApplicationRepository.submitOnceWithSession`, `touchJobOwner`, [MSC-01](specs/hiring-mongo-schema-consolidation.md) |
| Canonical value | The trimmed, root-locale lower-case form of a skill, city or country (`SearchTerm.canonical`). Stored beside the display value (`skillsCanonical`, `location.cityCanonical`, `profile.skillsCanonical`, residence sidecars) and applied to every filter input, so filters match ignoring case and surrounding spaces | Display value | `SearchTerm`, [MSC-08](specs/hiring-mongo-schema-consolidation.md) |
| Binary embedding vector | The stored form of an entity embedding: a float32 BSON binary vector (binData subtype 9) under `embedding`, written and read only by `MongoEmbeddingVectors` | Float64 array form | `MongoEmbeddingVectors`, [MSC-09](specs/hiring-mongo-schema-consolidation.md) |
| Subject fence | Per-user document in `outbox_subject_fences` written by account deletion and by guarded writes in the same transaction, so a write racing a deletion conflicts instead of committing for a deleted actor. Every writer uses the shared `MongoSubjectFence`: it reads the active account inside the transaction, then `$inc fencingVersion`; `users.version` is never touched. Callers: application submit/status change (`MongoApplicationWriteFence`, per actor, hot), the interview workflow (`fenceParticipants`/`fenceSubjects` in sorted order for several participants, and the hiring commit) and admin embedding-work authorization. The same document carries the publisher lease of the subject (`leaseEventId`, `leaseToken`, `leaseUntil`): one in-flight outbox event per subject, taken for the whole claimed batch in one bulk write and released per event | The account tombstone; a Saga compensation | `MongoApplicationWriteFence`, `fenceSubjects`, [ARR-02](specs/hiring-platform-refinements.md#completed-work-recorded-from-removed-specifications) |
| Query cost budget | Per-actor (or per-client-IP when anonymous) allowance of GraphQL complexity per time window, charged before execution | Request-count rate limit; the per-query complexity cap | ARR-14 |
| Schema exposure | Configuration that enables introspection and the SDL download; off in the production default | Authorization of data fields | `graphql.schema-exposure`, ARR-15 |
| Persisted-query allowlist | Optional mode (`graphql.persisted-queries.mode = allowlist`, default `off`) in which `/graphql` runs only full documents whose SHA-256 is listed in a startup-read manifest; others get HTTP 400 `PERSISTED_QUERY_NOT_FOUND`. Introspection-only documents are governed by schema exposure. Full documents only, no hash-only registration. See [API reference](api.md#persisted-query-allowlist) | Document cache; query cost budget; schema exposure | `graphql.persisted-queries`, `PersistedQueryAllowlist` |
| Error code | Closed GraphQL enum `ErrorCode` on `UserError.code`, derived from the failure catalog; top-level errors carry the same value as the string `extensions.code` | Free-form message text; HTTP status | `ErrorCode`, `GraphQLFailureCatalog` |
| Bounded top-N list | Search result list of at most N items from one ranking pass, with no cursor and no `pageInfo`, because the service cannot continue it | Paginated connection | `RankedJobResults`, `RankedCandidateResults` |
| Opaque cursor | The `Cursor` scalar: a compact HMAC-signed keyset position (`kind|fields|expiry`) that a client passes back as `after`; it fixes where a list continues and is re-authorized with every request, so it never grants access | A JWT, a credential, a client-built offset | `CursorCodec`, [graph access record](specs/hiring-platform-refinements.md#completed-work-recorded-from-removed-specifications) |
| Nested connection | A list field on a graph node (`Job.applications`, `Application.events`, `User.applications`) that runs the same authorized use case as the matching root query and is priced by `first` times its selection | A second authorization path; an unbounded list | `HiringGraphQLApplicationResolvers`, `QueryAdmission`, AC-07 |
| Time slot | A span of time with `startsAt` and `endsAt` (`TimeSlot`), used for the pending replacement and a reschedule proposal of an interview | A pair of loose timestamps | `InterviewInterval`, `TimeSlot` |
| Effect-polymorphic port | Service or repository port written over `F[_]` with the weakest Cats Effect capability it needs; `IO` is fixed only at Main, runtime wiring, configuration loading, IO adapters (Mongo, Kafka, auth, embedding) and the Sangria interop. See [effect-polymorphic services](specs/effect-polymorphic-services.md) | A generic framework, free algebra or transformer stack | `RepositoryF`, `UseCaseF` |
| Search recording failure | The operational fact (`SEARCH_RECORDING_FAILED`) that a search ran but its search session could not be recorded: search id, search kind and a bounded error code or exception class only. Published best-effort; it never changes the search response | Any query text, result id or message | `OperationalEventPayload.SearchRecordingFailed`, [AIR-04.3](specs/ai-search-resilience.md) |
| Search filter snapshot | The criteria a search session was run with, kept as a closed type (`JobCriteria` with city, sorted skills and optional created-after; `Unfiltered`; `ForJob`) instead of free-form JSON. Stored with the session; stored text decodes only as one of the three written shapes, otherwise the stored document is invalid. The API builds it from the request | The query text or the job-discovery request input | `SearchFilterSnapshot`, `SearchFilterWireCodec`, [ARR-09](specs/hiring-platform-refinements.md#completed-work-recorded-from-removed-specifications) |
| Degraded search | A ranked search answer produced by the lexical fallback because the query embedding provider (`ProviderUnavailable`) or `$vectorSearch` (`VectorSearchUnavailable`) was unavailable; it carries the reason (`degradedReason`, the only degradation signal) and its hits have mode `LEXICAL`, with no embedding model on the results. A missing or stale embedding is never degraded; it stays its own typed failure. If the fallback is also unavailable the result is `VectorSearchUnavailable`. Applies to `semanticJobSearch` and `candidateMatches` only, not `recommendedJobs` or facets | A partial result or an empty page; a retry | `DegradedSearch`, `SearchResults`, [AIR-05](specs/ai-search-resilience.md) |
| Lexical fallback | Keyword-only retrieval (`$search`, no vector, no provider call) used for a degraded search. It keeps every live eligibility check of the vector path (open job, filters, Candidate role, Active account, profile, consent-gated private filters, authorization) and drops only embedding freshness, then re-checks hits against current data. It shares search admission, `maxTimeMS` and the breaker with vector search and runs only after role, ownership and open-job checks | Hybrid search (lexical plus vector, normal mode); the `jobDiscoveryFacets` lexical match | `LexicalSearchQuery`, `SearchEligibilityPolicy.jobLexical`, `candidateLexical`, [AIR-06](specs/ai-search-resilience.md) |
| Relaxed filter | A search criterion (`createdAfter`, or skills changed from all-of to any-of) that guided discovery loosened because the original search found no eligible job. The response names it; nothing is relaxed silently (planned, GDF-01). | A changed ranking; relaxation never reorders results | `relaxedFilters` (planned) |
| Fit reason | The pair `matchedSkills` and `missingSkills` that explains a hit from data the caller can already see: a job's required skills against the candidate's own profile skills, or the owned job's required skills against a candidate's skills already in the result. Pure `SkillMatching` (`service/search/SearchContracts.scala`), GDF-02. | A score or rank; it is not shown in drafts | `matchedSkills`, `missingSkills` |
| Skill evidence | Distinct canonical job skills covered by the profile skills, out of the job's distinct canonical skills; absent when the job lists no skill or none is covered. With distinct canonical counts it equals matched over (matched plus missing) of the fit reason; a job that lists duplicate spellings makes the raw matched list longer than `covered`. Visible to the caller who can already see both inputs | A probability, a hiring-success measure or a count of skills the caller lists; it uses the job's skills only | `SkillEvidence` (HDQ-07 slices 1 and 2: implemented; not adopted, no production caller) |
| Skill-evidence ranking | A pure, deterministic ordering of hits by reciprocal rank fusion (k = 60) over retrieval rank and skill-evidence rank, ties by ascending retrieval rank. Not adopted and has no production caller; its fused value is internal and maps to no API field (owner decision Q7, option B, 2026-11-10) | The live default ranking (`SearchFusionStrategy`); any learned, LLM or personalized model | `SkillEvidenceRanking` (HDQ-07 slices 1 and 2: implemented; not adopted, no production caller) |
| Skill-evidence ranked strategy | The evaluation strategy case `SkillEvidenceRanked(underlying)`: a ranker applied to the authoritative output of a retrieval strategy, which it names. It exists only in test sources, is not a retrieval branch, and its report carries the tie-rule string (HDQ-07 slice 2: implemented; not adopted) | A retrieval branch; a live ranking | `SearchEvaluationStrategy.SkillEvidenceRanked` (test sources) |
| Latency noise allowance | A required, explicit number of milliseconds added to the baseline p95 before the ranker's p95 counts as a regression: ranked p95 above baseline p95 plus the allowance is `LatencyRegression`. Zero reproduces the strict comparison. The owner has not yet chosen a value (SEB-08 / HDQ-08) | A default or a tolerance for provider network latency | `SearchEvaluationAssessmentPolicy.latencyNoiseAllowanceMillis` (test sources) |
| Absolute p95 budget | A required, explicit p95 ceiling for a provider-generated capture (the owner's range is 2 to 5 seconds; the value is not yet chosen). Exceeding it gives the reason `AbsoluteLatencyBudgetExceeded` and the outcome Defer (proposed, open); it never feeds the relative rule, so provider latency alone cannot Reject the ranker | The relative latency rule; a service-level objective | `SearchEvaluationAssessmentPolicy.absoluteP95Budget` (test sources) |
| Provider-generated capture | An owner-started evaluation capture (the provider mode of `HiringSearchEvaluationAtlasRunner`, enabled by `--authorize-provider-embeddings`) in which the 16 fabricated corpus entities and the 12 query texts are embedded through the Voyage adapter, with provenance `ProviderGenerated`. It sends only fabricated text, makes 28 provider requests per invocation, and no test or API path starts it. A request count is not a billed amount, and the capture is not an adoption result | A synthetic-fixture capture (`SyntheticFixture`, the default); a live user-data embedding; observed billing | `SearchEvaluationEmbeddingProvenance.ProviderGenerated`, `ProviderEmbeddingCapture` (test sources), `HiringSearchEvaluationAtlasRunner` (`src/it`) |
| Data-collection attestation | The owner's statement of the Atlas organization's Voyage AI data-collection setting, given as `vector-search.voyage.data-collection-attestation` with the value `on` or `off`. It is required for a provider-generated capture, has no default, and is copied into the provider embedding evidence record. It is recorded, not enforced and not verified by the system | A verified privacy control; a provider contract; a default setting | `DataCollectionAttestation` (test sources), `vector-search.voyage.data-collection-attestation` |
| Provider embedding evidence record | The counts-and-identifiers JSON a provider-generated capture writes beside its reports: `provider-embedding-evidence-<concurrency>-<timestamp>.json` (outcome `Completed`, written before any Atlas work) or `provider-embedding-evidence-failed-<concurrency>-<timestamp>.json` (outcome is the refusal name, written after at least one request). It holds the endpoint host, model, dimension, attestation, budget, allowance and pause, the capture bound, the request count, and the provider-reported tokens per input and in total. It never holds the key, a vector, an input text or an exception text. After a failure its token total is a lower bound | The billed amount (the provider dashboard is the source, G8); a ranking or a report | `ProviderEmbeddingEvidence` (test sources) |
| Truncation guard | The check that refuses a ranked evaluation run whose captured list may have been cut at the declared capture bound. A ranked query is accepted only if its list is strictly shorter than `captureBound`, or the bound is at least `PageSize.Max`; a list of exactly the bound is refused as `PossiblyTruncatedCapture` (HDQ-07 slice 2: implemented; not adopted) | A live service check; proof that the eligible set was complete | `SkillEvidenceRankedEvaluation.rankedRun`, `SearchEvaluationError.PossiblyTruncatedCapture` (test sources) |

## Bounded contexts

| Context | Owns | Relationship |
|---|---|---|
| Hiring (operational) | Users, Jobs, Applications, history, workflow, outbox; MongoDB is the source of truth | Upstream of the others. Transactions never wait on them |
| Search and embedding | Retrieval, ranking, embedding work, search telemetry | Derives from Hiring data. Provider outage must not block hiring writes. Hydrates current public data for hits |
| Analytics | Spark/Delta projections and reports | Consumes operational events only and never gates transactions. It writes result snapshots back to MongoDB; operational decisions never read them |

Cross-context interaction goes through published events or explicit ports with their own types (an anti-corruption layer), not shared domain classes. A change that crosses a context line needs the Software Architect.

## Aggregates and invariants

| Aggregate | Invariant | Enforced by |
|---|---|---|
| Job | Valid Draft/Open/Closed transitions; closed means closed | Pure `JobLifecycle` program; persisted with a revision guard |
| Application (with its history) | Only permitted transitions; status and history change atomically; one Application per Candidate/Job; no submission to a closed Job | Pure `ApplicationLifecycle`; store-level unique index and transaction |
| Interview workflow | Own revisioned decision; adds no application statuses | Pure workflow decision in `domain/workflow`; revision guard |
| Application stage times (analytics read model, from lifecycle events) | One row per application; each stage keeps its earliest time and `lastEventAt` the latest; `terminalAt` and `expiresAt` are recomputed from the merged row; the candidate token is never updated; an erasure removes every row that names an erased subject token | `ApplicationStageTimes.merge` (MERGE on `applicationId` from a pre-aggregated source), `AnalyticsDeltaCatalog.ApplicationStageTimes` |
| User | Singleton Admin; role-specific profile; deleted accounts keep no profile | Domain constructors; store-level uniqueness |

Keep aggregates small. Reference other aggregates by typed ID, embed only bounded owned values, and change one aggregate per transaction unless an invariant spans two. Decisions are pure functions that return a new state or a typed error; services only sequence effects and authorize.

## Naming rules

- Types and values use glossary words. Domain events and history records are past-tense facts; commands and mutations are imperative actions.
- Value objects are typed IDs, enums and ADTs, not strings or booleans.
- Delivery phases, scaffolding and process labels never appear in names.
